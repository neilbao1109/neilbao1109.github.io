# Top-K 与 Top-P 采样详解

## 一、为什么需要它们？

LLM 词表通常有 **32,000~128,000** 个 token。即使经过 Temperature 调整，仍可能从极低概率的"垃圾 token"中采样，导致输出不连贯。

**Top-K 和 Top-P 的核心目的：截断概率分布的长尾，只从"合理"的候选词中采样。**

---

## 二、Top-K 采样

### 原理

> **只保留概率最高的 K 个 token，其余全部置零，然后对这 K 个 token 重新归一化后采样。**

### 流程图

```
原始概率分布 (词表大小 = 50,000)
    │
    ▼
按概率降序排列，只保留前 K 个
    │
    ▼
将保留的 K 个 token 概率重新归一化（使之和为 1）
    │
    ▼
从这 K 个 token 中按新概率采样
```

### 具体示例（K = 3）

| Token | 猫 | 狗 | 鸟 | 桌子 | 量子 | 哲学 | ... |
|:-----:|:--:|:--:|:--:|:----:|:----:|:----:|:---:|
| 原始概率 | 0.40 | 0.25 | 0.15 | 0.05 | 0.03 | 0.02 | ... |

Top-K = 3 后：

| Token | 猫 | 狗 | 鸟 | ~~桌子~~ | ~~量子~~ | ~~哲学~~ |
|:-----:|:--:|:--:|:--:|:------:|:------:|:------:|
| 截断 | 0.40 | 0.25 | 0.15 | ✗ | ✗ | ✗ |
| 归一化 | **0.500** | **0.3125** | **0.1875** | 0 | 0 | 0 |

### 代码实现

```python
import numpy as np

def top_k_sampling(logits, k):
    # 1. 找到 top-k 的索引
    top_k_indices = np.argsort(logits)[-k:]
  
    # 2. 将非 top-k 的 logits 设为 -inf
    filtered_logits = np.full_like(logits, -np.inf, dtype=float)
    filtered_logits[top_k_indices] = logits[top_k_indices]
  
    # 3. Softmax 归一化
    exp_logits = np.exp(filtered_logits - np.max(filtered_logits))
    probs = exp_logits / exp_logits.sum()
  
    # 4. 采样
    return np.random.choice(len(probs), p=probs)
```

### ⚠️ Top-K 的问题

```
场景 A：概率分布很集中          场景 B：概率分布很平坦
┌──────────────────────┐       ┌──────────────────────┐
│ ██████████  0.90     │       │ ███   0.08           │
│ █          0.05      │       │ ███   0.07           │
│ ▏          0.02      │       │ ██    0.06           │
│ ▏          0.01      │       │ ██    0.06           │
│ ▏          0.01      │       │ ██    0.05           │
│ ▏          0.01      │       │ ██    0.05           │
│  ...                 │       │ █    0.04            │
│  K=5 就够了          │       │ █    0.04            │
│                      │       │ ...                  │
│                      │       │ K=5 远远不够!         │
└──────────────────────┘       └──────────────────────┘
```

**K 是固定值，无法适应不同的概率分布形状** → 这正是 Top-P 要解决的问题。

## 三、Top-P（Nucleus Sampling）核采样

### 原理

> **按概率从高到低排序，累加概率直到总和 ≥ P，只保留这个最小集合中的 token，重新归一化后采样。**

### 流程图

```
原始概率分布
    │
    ▼
按概率降序排列
    │
    ▼
逐个累加概率，直到累积概率 ≥ P
    │
    ▼
只保留累积范围内的 token（"核/nucleus"）
    │
    ▼
重新归一化，采样
```

### 具体示例（P = 0.85）

| 排序 | Token | 概率 | 累积概率 | 是否保留 |
|:----:|:-----:|:----:|:--------:|:--------:|
| 1 | 猫 | 0.40 | 0.40 | ✅ |
| 2 | 狗 | 0.25 | 0.65 | ✅ |
| 3 | 鸟 | 0.15 | 0.80 | ✅ |
| 4 | 桌子 | 0.05 | **0.85** | ✅ ← 达到阈值 |
| 5 | 量子 | 0.03 | 0.88 | ❌ 截断 |
| 6 | 哲学 | 0.02 | 0.90 | ❌ |
| ... | ... | ... | ... | ❌ |

归一化后：

| Token | 猫 | 狗 | 鸟 | 桌子 |
|:-----:|:--:|:--:|:--:|:----:|
| 新概率 | **0.471** | **0.294** | **0.176** | **0.059** |

### 自适应的优势

```
场景 A：分布集中（P = 0.9）     场景 B：分布平坦（P = 0.9）
┌───────────────────────┐      ┌───────────────────────┐
│ ██████████  0.85 ✅   │      │ ███  0.08  ✅         │
│ █          0.06  ✅   │      │ ███  0.07  ✅         │
│ ---- 累积 0.91 截断 --│      │ ██   0.06  ✅         │
│ ▏          0.02  ❌   │      │ ██   0.06  ✅         │
│ ▏          0.01  ❌   │      │ ██   0.05  ✅         │
│                       │      │ ██   0.05  ✅         │
│ → 自动选了 2 个 token │      │ █    0.04  ✅         │
│                       │      │ █    0.04  ✅         │
│                       │      │ ...更多...  ✅         │
│                       │      │ ---- 累积 0.90 截断 --│
│                       │      │ → 自动选了 ~15 个token │
└───────────────────────┘      └───────────────────────┘
```

**Top-P 的候选集大小是动态的，自适应当前分布的形状！**

### 代码实现

```python
import numpy as np

def top_p_sampling(logits, p):
    # 1. Softmax 得到概率
    probs = np.exp(logits - np.max(logits))
    probs = probs / probs.sum()
  
    # 2. 降序排列
    sorted_indices = np.argsort(probs)[::-1]
    sorted_probs = probs[sorted_indices]
  
    # 3. 计算累积概率
    cumulative_probs = np.cumsum(sorted_probs)
  
    # 4. 找到累积概率超过 p 的位置，之后的全部移除
    cutoff_index = np.searchsorted(cumulative_probs, p) + 1
  
    # 5. 只保留 nucleus 中的 token
    nucleus_indices = sorted_indices[:cutoff_index]
    nucleus_probs = probs[nucleus_indices]
    nucleus_probs = nucleus_probs / nucleus_probs.sum()  # 归一化
  
    # 6. 采样
    chosen = np.random.choice(nucleus_indices, p=nucleus_probs)
    return chosen
```

## 四、完整采样流水线

```
          原始 logits（模型输出）
               │
               ▼
    ┌─────────────────────┐
    │    Temperature 缩放  │   logits = logits / T
    │    控制分布的尖锐度    │
    └──────────┬──────────┘
               ▼
    ┌─────────────────────┐
    │      Top-K 过滤      │   只保留概率最高的 K 个
    │    粗粒度截断长尾     │
    └──────────┬──────────┘
               ▼
    ┌─────────────────────┐
    │      Top-P 过滤      │   在 Top-K 结果中进一步
    │    细粒度自适应截断   │   按累积概率截断
    └──────────┬──────────┘
               ▼
    ┌─────────────────────┐
    │    归一化 + 采样      │   从最终候选集中
    │                     │   按概率随机抽取
    └──────────┬──────────┘
               ▼
          输出 token
```

## 五、参数对比总结

| 维度 | Top-K | Top-P |
|:----:|:-----:|:-----:|
| **控制方式** | 固定数量 | 固定累积概率 |
| **候选集大小** | 恒定 = K | 动态变化 |
| **自适应性** | ❌ 不适应分布变化 | ✅ 自动适应 |
| **典型值** | K = 10~100 | P = 0.8~0.95 |
| **极端值** | K = 1 → 贪心解码 | P = 1.0 → 不过滤 |
| **提出时间** | 较早（Fan et al., 2018） | 较晚（Holtzman et al., 2020） |

## 六、三个参数的协同效果

| 组合 | Temperature | Top-K | Top-P | 效果 |
|:----:|:-----------:|:-----:|:-----:|:----:|
| 最确定 | 0 | 1 | - | 纯贪心，永远选最高概率 |
| 保守 | 0.3 | 10 | 0.85 | 高质量、低变化 |
| 平衡 | 0.7 | 40 | 0.90 | 质量与多样性兼顾 |
| 创意 | 1.2 | 100 | 0.95 | 高多样性、偶有惊喜 |
| 最随机 | 2.0 | 50000 | 1.0 | 近乎随机，可能胡言乱语 |

## 七、直觉类比

```
想象你在餐厅点菜，菜单有 1000 道菜：

🌡️ Temperature = 缩放你对每道菜的偏好评分差距
   低温：你超爱的菜评分拉到极高，其他几乎为0
   高温：所有菜评分差不多，你变得"选择困难"

🔢 Top-K = "我只看菜单前 K 道热门菜"
   不管今天心情如何，永远只考虑固定数量的选择

📊 Top-P = "我从最想吃的开始往下看，直到覆盖了 90% 的食欲"
   特别想吃某道菜时 → 只看 1-2 道
   没什么特别想吃的 → 多看几道再决定
```

## 八、实践建议

```
📝 事实性任务（问答、翻译、代码）:
   Temperature = 0~0.3, Top-P = 0.8~0.9, Top-K = 10~20

💬 日常对话:
   Temperature = 0.5~0.8, Top-P = 0.85~0.95, Top-K = 40

🎨 创意任务（写诗、故事、brainstorm）:
   Temperature = 0.9~1.3, Top-P = 0.90~0.95, Top-K = 50~100

⚠️ 通常 Top-P 比 Top-K 更推荐使用，
   因为它能自适应不同语境下的概率分布变化。
   很多 API（如 OpenAI）默认推荐只调 Temperature + Top-P。
```
